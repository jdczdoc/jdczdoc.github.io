# Compilation and Flashing

## Prerequisites

- Download rkbin

  This is a tool package repository for storing Rockchip's closed-source binaries, scripts, and packaging tools. During U-Boot compilation, it indexes related files from this repository to generate loader, trust, and uboot firmware. The rkbin and U-Boot projects must be kept at the same directory level.

  > Repository download: please refer to the appendix chapter.

- Download GCC

  The GCC compiler uses gcc-linaro-6.3.1, placed in the prebuilts directory. prebuilts and U-Boot must be at the same directory level. As follows:

  ```c
  // 32-bit:
  prebuilts/gcc/linux-x86/arm/gcc-linaro-6.3.1-2017.05-x86_64_arm-linux-gnueabihf
  // 64-bit:
  prebuilts/gcc/linux-x86/aarch64/gcc-linaro-6.3.1-2017.05-x86_64_aarch64-linux-gnu/
  ```

  > GCC download: please refer to the appendix chapter

- Introduction to config fragment

  Due to differentiated product requirements on a single platform, a single defconfig is no longer sufficient. Starting from RV1126, config fragment is supported, i.e., overlaying on top of a defconfig.

  For example: rv1126-emmc-tb.config specifies `CONFIG_BASE_DEFCONFIG="rv1126_defconfig"`. When executing `./make.sh rv1126-emmc-tb`, it first generates .config using rv1126_defconfig, then overlays the configuration from rv1126-emmc-tb.config onto .config. This command is equivalent to:

  ```
  make rv1126_defconfig rv1126-emmc-tb.config && make
  ```

  To update the config fragment file, simply use `./scripts/sync-fragment.sh`. For example:

  ```
  ./scripts/sync-fragment.sh configs/rv1126-emmc-tb.config
  ```

  Effect: diffs the configuration differences between the current .config and rv1126_defconfig into the rv1126-emmc-tb.config file.

## Firmware Compilation

Compilation command:

```c
./make.sh [board]               // [board]: configs/[board]_defconfig file.
```

**First compilation**: Regardless of 32-bit or 64-bit platform, for the first time or when re-specifying a defconfig, the compilation command must specify [board]. For example:

```c
./make.sh rk3399                // build for rk3399_defconfig
./make.sh evb-rk3399            // build for evb-rk3399_defconfig
./make.sh firefly-rk3288        // build for firefly-rk3288_defconfig
```

**Subsequent compilation**: Regardless of 32-bit or 64-bit platform, to compile based on the current ".config" without re-specifying [board]:

```
./make.sh
```

> Note: If strange issues cause compilation failure, try `make distclean` and recompile.

**Firmware generation**: After compilation, trust, uboot, and loader are packaged in the U-Boot root directory. Below is the information during packaging:

The final flashable firmware is generated in the root directory:

```c
./uboot.img
./trust.img    // Note: For fit format firmware, there is no trust.img. The trust binary is packaged inside uboot.img.
./rk3126_loader_v2.09.247.bin
```

## Firmware Flashing

**Flashing tool**:

For Windows/Linux firmware flashing tools, it is recommended to use the tool version from the SDK release or the latest version.

**Flashing mode**:

RK platforms support two flashing modes: Maskrom mode and Loader mode (U-Boot).

(1) Entering Loader flashing mode:

- Press and hold Volume+ during boot
- Press and hold ctrl+d on the host during boot
- U-Boot command line input: download or rockusb 0 \$devtype $devnum

(2) Entering Maskrom flashing mode:

- Press and hold ctrl+b on the host during boot
- U-Boot command line input: rbrom

**Notes:**

- Currently U-Boot supports two partition table types: RK parameter partition table (old) and GPT partition table (new). To switch from one partition table type to the other, Nand devices must have the entire firmware re-flashed; eMMC devices support replacing the partition table independently.

- If both partition tables exist on the device, GPT partition table is recognized first. This can be confirmed via boot information:

  ```c
  ...
  PartType: EFI // Currently using GPT partition table; otherwise prints "PartType: RKPARM"
  ...
  ```

## Special Packaging

In addition to compiling code, ./make.sh also integrates firmware packaging functionality. Some additional standalone packaging commands are provided for developers. However, U-Boot must be compiled at least once before using them.

Non-FIT format:

```c
./make.sh trust              // Package trust
./make.sh loader             // Package loader
./make.sh trust <ini-file>   // Specify ini file when packaging trust; otherwise use default ini file
./make.sh loader <ini-file>  // Specify ini file when packaging loader; otherwise use default ini file
```

FIT format:

```c
// Old script:
./make.sh spl                // Replace ddr and miniloader with tpl+spl, package as loader
./make.sh spl-s              // Replace miniloader with spl, package as loader

// New script:
./make.sh --spl              // Replace miniloader with spl, package as loader
./make.sh --tpl              // Replace ddr with tpl, package as loader
./make.sh --tpl --spl        // Replace ddr and miniloader with tpl and spl, package as loader
./make.sh --spl-new          // ./make.sh --spl only packages without compiling; this command recompiles then packages.
```

> How to distinguish old and new scripts? If the new commands work, make.sh is the new script.
